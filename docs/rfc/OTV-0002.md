# OTV-0002 Terminology

**Status:** Accepted  
**Version:** 0.1.0

## Abstract

Shared vocabulary so wallets, explorers, and the API do not collapse distinct facts.

## Terms

| Term | Meaning |
|------|---------|
| Claim | Client assertion about an incoming transfer (`IncomingClaim`) |
| Observation | Recorded chain fact (tx, receipt, log, balance) |
| Evidence | Typed PASS/FAIL item attached to a verdict |
| Verdict | Signed `otv.verdict.v1` object |
| Trust state | One of the explicit `VerificationStatus` enum values |
| Spendable | Policy conclusion that value is usable by the recipient — not “seen on chain” |
| Adapter | Chain-specific RPC façade implementing `ChainAdapter` |
| Kid | Signing key identifier |
| Project | Tenant isolation unit under an organization |

## Status enum (normative)

`OBSERVED`, `PENDING`, `EXECUTED`, `ASSET_CONFIRMED`, `BALANCE_CONFIRMED`, `FINAL`, `SPENDABLE`, `REJECTED`, `SUSPICIOUS`, `UNVERIFIED`.

Transitions: `packages/verdict-schema` `assertTransition`.
